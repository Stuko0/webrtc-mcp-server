1. ¿Qué es WebRTC MCP Server?

WebRTC MCP Server v0.4.0 es un servidor Model Context Protocol (MCP) (protocol v2025-03-26) que expone 16 herramientas WebRTC para Lydia Agent y otros agentes de código compatible. Permite comunicación peer-to-peer multi-agente en tiempo real (Lydia ↔ OpenCode ↔ Claude Code) mediante DataChannels de baja latencia, coordinación mediante rooms y streams de video RTSP/HLS con procesamiento de frames.

Nota: Sigue la Footprint Ladder de Lydia (approach #2 del análisis de grafos): MCP server externo, no un core tool. Cero cambios en toolsets.py, model_tools.py o run_agent.py. El agente descubre las herramientas vía el cliente MCP built-in.

2.2 Señalización (Signaling)

WebRTC requiere un canal de señalización para intercambiar SDP (Session Description Protocol) e ICE candidates. El servidor MCP expone:

  • WebSocket Signaling: Peers externos (OpenCode) conectan vía WS. El server WebSocket intercambia SDP/ICE entre peers del mismo room.
  • MCP stdio Signaling: Lydia actúa como peer. El MCP server (Node.js) crea la RTCPeerConnection interna y la señalización fluye vía MCP tool calls (webrtc_connect, webrtc_send).

Flow típico multi-agente:

1. Lydia: webrtc_create_room("webrtc-test")
2. OpenCode (via WS): {type:"join", peerId:"open-code", room:"webrtc-test"}
3. Lydia: webrtc_connect(peerId="open-code") → RTCPeerConnection + DataChannel
4. Se intercambian SDP/ICE vía webrtc_signal_relay o WS relay
5. Una vez ICE connected → DataChannel lista para mensajes
6. Lydia ↔ OpenCode: webrtc_send(peerId, data) bidireccional

6. Integración con Lydia

6.1 Instalación como MCP server

El servidor se instala como MCP estándar. Lydia descubre las herramientas vía el cliente MCP built-in (protocol v2025-03-26 sobre stdio JSON-RPC).

# Instalar el MCP server (como plugin local)
cd ~/Jobs/Arquant/lydia-agent
lydia mcp remove webrtc 2>/dev/null
lydia mcp add webrtc \
  --command "node" \
  --args "/home/stuko/Jobs/Arquant/webrtc-mcp-server/dist/index.js" \
  --env "WEBRTC_SIGNALING_MODE=stdio,WEBRTC_MAX_WORKERS=8,WEBRTC_LOG_LEVEL=warn"

# Verificar
lydia mcp list
# → webrtc │ running │ 16 tools registered

# Probar
lydia mcp call webrtc webrtc_health

6.3 Skill webrtc-monitoring

Skill en scripts/SKILL.md — el agente lo carga cuando el usuario pide monitoreo en tiempo real. Permite:

  • Conectar a cámara RTSP → frame → vision_analyze
  • Monitoreo periódico (cron job)
  • Listar streams activos

6.4 Integración con vision_analyze

Flujo principal: connect_stream → frame_get → vision_analyze → respuesta del agente.

# Pseudocódigo del agente
1. stream = await mcp.call("webrtc", "webrtc_connect_stream", {"url": "rtsp://cam:554/stream1"})
   → {stream_id: "cam-entrada", offer_sdp: "...", ice_servers: [...]}
2. frame = await mcp.call("webrtc", "webrtc_frame_get", {"stream_id": "cam-entrada"})
   → {frame: "base64...", timestamp: ..., resolution: {w:1920, h:1080}}
3. analysis = await tools.call("vision_analyze", {"image": "data:image/jpeg;base64,...", "question": "¿Hay personas?"})
4. if "persona" in analysis: send_message("¡Alguien en la entrada!")

Optimización: El frame se cachea (ring buffer de 5 frames). Si el frame no cambió, se devuelve el mismo buffer. No se re-codifica JPEG innecesariamente.

8. Seguridad

8.1 Modelo de amenazas

AmenazaMitigación
Stream no autorizadoValidación de protocolo: solo rtsp://, rtmp://, https://. URLs se validan contra allowlist configurable (default: red local 192.168.x.x, 10.x.x.x).
Exfiltración vía WebRTCEl MCP server corre en el contexto del agente. Solo Lydia/OpenCode pueden llamar herramientas — no hay API externa expuesta.
DoS por muchos streamsLímite de workers (default 8, configurable hasta 16). Cola de espera para requests extras.
Credenciales en URLsLas URLs se almacenan en memoria, no en disco ni logs. Se trunca la contraseña en respuestas.

8.2 Permisos en Electron

Si se combina con screen sharing desde Electron (fase posterior), modificar apps/desktop/electron/main.cjs:

function isMediaPermission(permission, details) {
  if (permission === 'audioCapture') return true;
  // NEW: Allow video screen capture
  if (permission === 'videoCapture') return true;
  if (permission === 'media') return false;
  ...
}

Warning: El permission handler actual deniega video explícitamente. Habilitarlo requiere que el usuario apruebe explícitamente el acceso a cámara/pantalla.

10. Uso para Usuarios (agentes)

10.1 Escenario multi-agente: Lydia + OpenCode

Setup completo documentado en tmp/ — 16 tools conectadas a Lydia, OpenCode cliente WS conectado a room webrtc-test.

# Paso 1 (Lydia): crear room y conectar
> webrtc_create_room("webrtc-test")
> webrtc_connect(peerId="open-code")
→ {peerId: "open-code", status: "connected", dataChannels: ["default"]}

# Paso 2 (OpenCode vía WS): joiner room
{"type":"join","peerId":"open-code","room":"webrtc-test"}
→ {"type":"joined","peerId":"open-code","room":"webrtc-test"}

# Paso 3: comunicación bidireccional
> webrtc_send(peerId="open-code", data={"task":"code-review","file":"src/index.ts"})
→ OpenCode recibe el mensaje vía DataChannel o WS relay

> webrtc_send(peerId="lydia", data={"result":"✅ review complete, 0 issues found"})

10.2 Escenario monitoreo de cámaras

# Conectar a cámara IP
> webrtc_connect_stream(url="rtsp://admin:pass@192.168.1.100:554/stream1")
→ {stream_id: "cam-entrada", offer_sdp: "...", ice_servers: [...]}

# Obtener frame y analizar
> webrtc_frame_get(stream_id="cam-entrada")
→ {frame: "base64...", timestamp: 1785565495825, resolution: {width:1920, height:1080}}

> vision_analyze(image="data:image/jpeg;base64,...", question="¿Hay personas?")
→ "Sí, hay 2 personas en la escena."

# Listar streams
> webrtc_list_streams()
→ {streams: [{id:"cam-entrada", status:"connected", ...}]}

10.3 Cron: monitoreo periódico

# Cada 5 minutos, revisar cámara y detectar movimiento
> /cron create "every 5m" "Conecta a la camara RTSP, toma frame, analiza con vision_analyze y reporta si hay personas"
